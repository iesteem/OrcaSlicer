概述

--auto-export-gcode 是 Snapmaker Orca 新增的命令行选项， 用于在无界面模式下批量切片 3MF 文件。它会自动加载 3MF 项目、 切片所有盘（plate）、导出 G-code 3MF，然后退出。

典型用途：

  • CI/CD 流水线中的自动切片
  • 批量切片大量 3MF 文件（一次进程调用处理多个文件，避免重复启动开销）
  • 服务器端自动化切片任务
  • 外部脚本需要精确的切片进度和详细结果报告

快速开始

最简单的用法 —— 切片一个 3MF：

SNAPMAKER_ORCA_ALLOW_NEWER_FILE=1 snapmaker-orca \
  --auto-export-gcode /tmp/out /path/to/model.3mf

切片两个 3MF：

SNAPMAKER_ORCA_ALLOW_NEWER_FILE=1 snapmaker-orca \
  --auto-export-gcode /tmp/out a.3mf b.3mf
⚠ 环境变量必需

SNAPMAKER_ORCA_ALLOW_NEWER_FILE=1 必须设置，否则较新版本的 3MF 文件 会被加载校验拒绝。该变量绕过 3MF 版本兼容性检查（GUI 模式正常工作，CLI 不行）。

命令语法

snapmaker-orca --auto-export-gcode <输出目录> <3mf文件> [<3mf文件> ...]
参数说明必填
--auto-export-gcode <dir> 触发自动切片模式；值为输出目录路径（不存在会自动创建） 是
<3mf文件> 一个或多个 3MF 文件路径，按顺序处理 是（至少 1 个）
SNAPMAKER_ORCA_ALLOW_NEWER_FILE=1 环境变量；允许加载较新版本的 3MF 文件 是

单文件模式

传入一个 3MF 文件即为单文件模式。

Linux / macOS

SNAPMAKER_ORCA_ALLOW_NEWER_FILE=1 snapmaker-orca \
  --auto-export-gcode /tmp/out /path/to/model.3mf

Windows (Git Bash / WSL)

SNAPMAKER_ORCA_ALLOW_NEWER_FILE=1 snapmaker-orca.exe \
  --auto-export-gcode "C:/out" "C:/path/model.3mf"

Windows (PowerShell)

$env:SNAPMAKER_ORCA_ALLOW_NEWER_FILE=1
snapmaker-orca.exe --auto-export-gcode "C:\out" "C:\path\model.3mf"

Windows (CMD)

set SNAPMAKER_ORCA_ALLOW_NEWER_FILE=1
snapmaker-orca.exe --auto-export-gcode "C:\out" "C:\path\model.3mf"

输出产物

文件说明
<dir>/<stem>.gcode.3mf 切片结果（G-code + 模型，可直接发送到打印机）
<dir>/<stem>.result.json 详细切片报告（per-plate 状态、耗时、警告、G-code 行数）

<stem> 是输入 3MF 文件名（不含扩展名）。

多文件模式

传入多个 3MF 文件即为多文件模式。所有文件在一个进程内顺序处理：

  1. 加载第 1 个文件 → 切片 → 导出
  2. 清空当前项目，加载第 2 个文件 → 切片 → 导出
  3. …依此类推
  4. 所有文件完成后写 summary.json，进程退出
SNAPMAKER_ORCA_ALLOW_NEWER_FILE=1 snapmaker-orca \
  --auto-export-gcode /tmp/out a.3mf b.3mf c.3mf

输出产物

文件说明
<dir>/<stem1>.gcode.3mf 第 1 个文件的切片结果
<dir>/<stem1>.result.json 第 1 个文件的详细报告
<dir>/<stem2>.gcode.3mf 第 2 个文件的切片结果
<dir>/<stem2>.result.json 第 2 个文件的详细报告
<dir>/summary.json 仅多文件模式产生；汇总所有文件的状态
💡 多文件模式的优势

进程启动开销约 10 秒。多文件模式下，N 个文件只需启动一次进程， 相比外部 shell 循环调用 N 次单文件模式，可节省大量时间。

进度跟踪

切片过程中，stderr 会实时输出进度。重定向到日志文件：

snapmaker-orca --auto-export-gcode /out model.3mf 2>progress.log

输出格式

# 切片开始
[auto-export] slicing all: file=model, plates=8

# 单盘进度（按 5% 粒度节流）
[auto-export] plate 1/8: 5%
[auto-export] plate 1/8: 15%
[auto-export] plate 1/8: 25%
...
[auto-export] plate 1/8: 100%

# 切换到下一盘
[auto-export] plate 2/8: 5%
...

# 导出阶段
[auto-export] exporting: /out/model.gcode.3mf
[auto-export] done: model (61.6s, 49878173 bytes)

# 多文件模式下，加载下一个文件
[auto-export] loading: /path/to/next.3mf

# 全部完成（仅多文件模式）
[auto-export] all files done: ok=2, failed=0
💡 实时进度解析

CI/脚本可逐行读取 stderr，正则匹配 plate (\d+)/(\d+): (\d+)% 实时显示当前切片的盘序号和百分比。

退出码

退出码含义说明
0 全部成功 所有文件、所有盘切片+导出成功
-1 切片失败 切片过程产生错误；多文件模式下任一文件失败即返回 -1
-2 导出失败 切片成功但 export_3mf 返回非 0
-3 未捕获异常 导出阶段抛出 std::exception 或未知异常

脚本示例

Bash：切片当前目录所有 3MF 并检查结果

#!/bin/bash
set -e
OUT=/tmp/slice_out
mkdir -p $OUT

export SNAPMAKER_ORCA_ALLOW_NEWER_FILE=1
snapmaker-orca --auto-export-gcode $OUT *.3mf 2>$OUT/progress.log
EXIT=$?

if [ $EXIT -ne 0 ]; then
  echo "切片失败，退出码 $EXIT"
  cat $OUT/summary.json 2>/dev/null
  exit $EXIT
fi

# 检查每个文件的盘切片状态
python3 -c "'
import json, os
summary = json.load(open(\"$OUT/summary.json\"))
for r in summary[\"results\"]:
    stem = os.path.splitext(os.path.basename(r[\"file\"]))[0]
    j = json.load(open(f\"$OUT/{stem}.result.json\"))
    failed = j[\"failed_plates\"] + j[\"skipped_plates\"]
    status = \"✓\" if failed == 0 else \"✗\"
    print(f\"{status} {j['input_file']}: ok={j['sliced_plates']}, failed={failed}, time={j['total_time_sec']:.1f}s\")
'"

Python：解析进度并实时显示

import subprocess, re, sys

cmd = ["snapmaker-orca", "--auto-export-gcode", "/out", "model.3mf"]
env = {"SNAPMAKER_ORCA_ALLOW_NEWER_FILE": "1", "PATH": os.environ["PATH"]}

proc = subprocess.Popen(cmd, env=env, stderr=subprocess.PIPE, text=True)
for line in proc.stderr:
    m = re.search(r"plate (\d+)/(\d+): (\d+)%", line)
    if m:
        plate, total, pct = m.groups()
        sys.stdout.write(f"\r切片中: 盘 {plate}/{total} - {pct}%")
        sys.stdout.flush()
proc.wait()
print(f"\n完成，退出码 {proc.returncode}")

PowerShell：批量切片

$env:SNAPMAKER_ORCA_ALLOW_NEWER_FILE = 1
$out = "C:\slice_out"
New-Item -ItemType Directory -Force -Path $out | Out-Null

$files = Get-ChildItem -Filter *.3mf | Select-Object -ExpandProperty FullName
& snapmaker-orca.exe --auto-export-gcode $out @files 2> $out\progress.log

if ($LASTEXITCODE -eq 0) {
    Write-Host "全部切片成功" -ForegroundColor Green
} else {
    Write-Host "切片失败，退出码 $LASTEXITCODE" -ForegroundColor Red
    Get-Content $out\summary.json
}

注意事项

⚠ 必需环境变量

SNAPMAKER_ORCA_ALLOW_NEWER_FILE=1 必须设置，否则较新版本 3MF 文件 会被加载校验拒绝（出现 "File Version X.X.X.X not supported" 错误）。

⚠ 文件覆盖

输出文件名固定为 <stem>.gcode.3mf 和 <stem>.result.json。 多次运行会覆盖已有产物。多文件模式下若多个 3MF 的 stem 相同（如 dir1/model.3mf 和 dir2/model.3mf），产物会互相覆盖。

💡 输出目录自动创建

--auto-export-gcode 指定的输出目录如果不存在，会自动递归创建。

💡 中文文件名支持

完整支持 UTF-8 文件名，包括中文（如 圣诞小屋模型.3mf）。 Windows 上建议使用 PowerShell 或 Git Bash，避免 CMD 的编码问题。

💡 filament_mm 字段

当前版本 filament_used_mm 和 plates[].filament_mm 均为 null，已在 JSON 中标记 TODO。计划在 v2 实现从 print_statistics.model_volumes_per_extruder 计算每盘耗材长度。

常见问题

Q1：报错 "File Version X.X.X.X not supported by current cli version"

未设置环境变量。请确保运行前设置 SNAPMAKER_ORCA_ALLOW_NEWER_FILE=1。

Q2：切片过程没有任何 stdout 输出

这是设计如此。进度走 stderr，stdout 默认无输出。如需查看进度， 请重定向 stderr：2>progress.log。

Q3：进程跑很久后崩溃或卡住

可能原因：

  • 3MF 文件损坏（尝试用 GUI 模式打开验证）
  • 内存不足（大模型 + 多盘，需要 8GB+ RAM）
  • 某些盘的模型有问题（检查 <stem>.result.json 的 failed_plates）

Q4：如何只切片部分盘？

当前版本不支持选择盘范围。所有非空盘都会被切片。 若需跳过空盘，留空即可（自动标记为 skipped）。

Q5：单文件模式为什么没有 summary.json？

设计决定：单文件模式产物是 <stem>.result.json， 信息已完整。summary.json 仅在多文件模式（>1 个输入文件）下产生。

Q6：输出文件为什么还是 3MF 不是 G-code 文本？

.gcode.3mf 是包含 G-code 的 3MF 容器格式，是 Snapmaker 打印机的标准输入。 打开它可以看到内嵌的 G-code（通常在 Metadata/ 目录下）。 如需纯文本 G-code，可解压 3MF 提取。

Q7：如何禁用 3MF 兼容性检查不靠环境变量？

目前只能通过环境变量 SNAPMAKER_ORCA_ALLOW_NEWER_FILE=1。 该选项本身有 CLI 入口 --allow-newer-file，但存在参数解析限制， 无法直接作为命令行参数传入。环境变量是当前推荐方式。
