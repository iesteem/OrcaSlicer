# G-code 输出

这些设置控制 G-code 的生成与格式。它们影响可读性、文件大小、打印行为以及与固件和后处理工具的兼容性。

## 减少填充回抽

启用后，切片器将跳过完全发生在填充区域内部的空驶移动的回抽。这减少了回抽次数，可以加快复杂模型的打印，但可能增加填充内部的渗料或拉丝。切片时间也可能略微增加。

当内部外观质量不重要且想减少回抽时**推荐**使用。

## 添加行号

为每行 G-code 加上行号前缀（N1, N2, ...）。适用于调试或需要带行号 G-code 的工具。

## 详细 G-code

为 G-code 行和块添加描述性注释，使文件人类可读、便于调试。
详细模式生成的文件大得多，并可能拖慢某些打印机的 SD 卡打印。

## 标记对象

插入注释，标记每段移动属于哪个对象（对象索引或名称）。这对 OctoPrint 的 Cancel Object 插件等集成以及人工检查 G-code 很有用。

> [!IMPORTANT]
> 对象标记与单挤出机多材料配置以及"擦入对象"/"擦入填充"策略不兼容。
> 当这些功能启用时，标记可能被省略。

## 排除对象

为标记为排除的对象在导出的 G-code 中添加 `EXCLUDE OBJECT` 标记或命令。这有助于后处理器或自定义脚本识别被排除的零件。

## 文件名格式

为导出的 G-code 定义文件名模板。模板可包含项目名、日期等令牌，以在导出时生成一致且信息丰富的文件名。

例如：

```c++
{input_filename_base}_{filament_type[initial_tool]}_{print_time}.gcode
```

可用于生成类似 `OrcaCube_PLA_1h15m.gcode` 的文件名。

> [!TIP]
> 可用令牌及其含义请查看[内置占位符变量](built-in-placeholders-variables)。
