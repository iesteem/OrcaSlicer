# GUI 层宪章（Charter）

> 状态：草案 v0.1（2026-09-09）
> 本文件定义 GUI 层**为何存在、长期愿景与边界**。它是 GUI 任何重大重构（包括由 AI 进行的整体重写）的最高约束。
> 与 [方法论](02_METHODOLOGY.md)、[用例](03_USE_CASES.md) 配套阅读。分级标注约定见方法论 §1。

## 1. 存在理由

本 GUI 是 Snapmaker 3D 打印机的官方切片软件入口。它存在的唯一理由是：

**让 Snapmaker 机器的用户能够可靠地把一个数字模型变成一次成功的打印。**

一切子目标——多色、校准、网络发送、耗材管理——都服务于这一句话。任何不能追溯到该目标的 GUI 功能，都是候选的裁剪对象；任何阻碍该目标的功能缺陷，都是最高优先级。

## 2. 长期愿景

- **可信赖的切片工具**：用户敢于把昂贵耗材和数小时打印托付给它的预览与输出。
- **多机型/多耗材的驾驭者**：Snapmaker 多机型（含换料、擦除塔等场景）的复杂性由软件吸收，而不是转嫁给用户。
- **行为可预期的演进**：用户升级版本后，其数据、配置与肌肉记忆不被破坏。

## 3. 边界（不做什么）

1. 不做与切片/打印无关的通用 3D 建模。
2. 不引入强制的云端账户依赖——本地切片能力必须在离线状态下完整可用。`[MUST]`
3. 不破坏项目文件的前向/后向兼容（见方法论 §4 数据契约）。
4. 不以牺牲输出正确性换取界面响应速度；宁可阻塞并明示，不可静默产出错误的 G-code。`[MUST]`

## 4. 不可违背的原则

以下原则数量刻意极少。每一条都源自历史上真实付出过的代价。

| # | 原则 | 级别 |
|---|------|------|
| P1 | **用户数据永不隐式遗失**：任何配置、profile、机器绑定信息，不得在未经用户明确提示与手动确认的情况下丢失或不可逆改写（含版本升级、机型切换、转储文件损坏恢复等一切路径） | `[MUST]` |
| P2 | **所见即所切**：预览渲染必须与实际切片输出一致；任何影响 G-code 的参数变化必须在预览中可见 | `[MUST]` |
| P3 | **错误必可见**：切片失败、发送失败、配置冲突必须显式呈现给用户，禁止吞错后继续 | `[MUST]` |
| P4 | **离线可用**（见边界 2） | `[MUST]` |
| P5 | **长任务可取消**：切片、发送等耗时操作必须可中断，且中断后状态一致 | `[MUST]` |
| P6 | **平台一致**：Windows / macOS / Linux 三平台上，用例级别的行为语义一致（像素级样式允许差异） | `[MUST]` |

## 5. 体验稳定性锚定模型（默认模型）

GUI 重构（"转生"）时，按以下三层区别对待：

| 层 | 锚定程度 | 说明 |
|---|---|---|
| **L0 数据与输出** | 死锁：字节/语义级兼容 | 3MF、G-code、profile 读写、机器绑定数据。详见方法论 §4 |
| **L1 核心操作语义** | 锁行为不锁实现 | 同样的入口 + 手势 → 同样的结果。入口的菜单位置/快捷键属于语义；内部实现任意 |
| **L2 视觉与布局** | 只锁约定不锁样式 | 主题/明暗色/DPI 适配是 `[MUST]`；控件具体样式、面板排列属于 `[CURRENT]` |

未明确归层的交互，默认归入 L2；归层争议记录在用例文档附录 A，由维护者裁决。

## 7. 文档本身的治理

- 宪章变更需维护者显式批准，并在 git 历史中留下理由。
- 当宪章与代码现状冲突时：宪章优先，代码是缺陷（或在例外名单中）。
- 每次转生（大规模重构）前后，本文档必须复核一次。
