# GUI 层方法论（Methodology）

> 状态：草案 v0.1（2026-09-09）
> 定义 GUI 层的基本方法论与硬规则。这些规则约束**任何实现**（人写的、AI 增量修补的、AI 整体重写的）。

## 1. 分级标注约定

全系列文档使用三级标注，这是"转生"能否安全进行的关键机制：

| 标注 | 含义 | 违反后果 |
|------|------|----------|
| `[MUST]` | 转生不可破坏的行为契约 | 转生失败，必须修复后重验 |
| `[SHOULD]` | 强烈建议，偏离需在 PR/重构说明中记录理由 | 允许，但需留痕 |
| `[CURRENT]` | 仅描述现状，新实现可自由改进 | 无 |

判定规则：拿不准时先标 `[CURRENT]`，由维护者升级；**不允许把拿不准的标成 `[MUST]`**——膨胀的 MUST 列表会让转生窒息。

## 2. 技术基线约定

- GUI 框架：wxWidgets。转生时**允许**更换框架，但 L1 语义与 L0 数据契约不变，且三平台支持（宪章 P6）必须保持。`[SHOULD]`
- 渲染：OpenGL。实时预览渲染与切片结果的一致性受宪章 P2 约束。`[SHOULD]`
- 并发：耗时计算不阻塞 UI 线程；UI 线程不执行几何计算。`[MUST]`
- 线程安全：跨线程访问 GUI 状态必须经由事件/消息传递。`[MUST]`

## 3. 数据流规则

1. **单一配置事实源**：所有切片参数经由配置体系（PrintConfig）读写，GUI 不得旁路维护参数副本。`[MUST]`
2. **参数变更可追溯**：每个参数修改必须能反映到预设的"已修改"标记与差异视图中。`[MUST]`
3. **切片管线的原子性**：后台切片过程（BackgroundSlicingProcess 语义）完成前，输出文件不得处于半成品状态。`[MUST]`
4. **撤销/重做**：对物体级操作（增删、变换）提供撤销；参数修改的撤销为 `[SHOULD]`。

## 4. 数据契约（L0，死锁层）

以下格式是**继承面**，转生时必须原样继承，任何变更都视为对宪章的修订：

| 契约 | 内容 | 兼容性要求 |
|------|------|-----------|
| 项目文件 | 3MF / BBS_3MF 读写 | 旧版本文件必须可读；写入格式向后兼容 |
| 打印输出 | G-code（含机器后处理语义） | 相同输入配置 → 相同语义的 G-code |
| 配置体系 | PrintConfig 全部配置项、profile JSON（resources/profiles，约 8700 文件） | 配置项不可移除、不可改名换义；默认值变更需迁移逻辑 |
| 用户状态 | 预设的用户新建/修改副本、机器绑定、AMS 映射、校准历史 | 宪章 P1 全程生效 |
| 资源 | 语言包覆盖的字符串集合 | 既有翻译不得静默失效 |

## 5. UI 一致性约定

- 明/暗主题双适配、高 DPI 缩放正确。`[MUST]`
- 所有面向用户的字符串经 i18n 体系，不硬编码自然语言。`[MUST]`
- 危险操作（删除配置、重置预设、覆盖文件）需二次确认。`[MUST]`
- 长任务必须有进度指示与取消途径（宪章 P5）。`[MUST]`

## 6. 与 dev-guidelines harness 体系的关系

本系列文档**不取代** `C:\code\dev-guidelines` 中的编码/评审 harness：

- harness 管束"代码怎么写"（增量修补时的质量）；
- 本文档管束"软件必须做什么"（转生时的等价性）。
- 实现与评审时两者都加载；冲突时以本文档的行为契约为准，编码规范以 harness 为准。

## 7. 验收机制

- 每个用例（03_USE_CASES.md）自带验收锚点：默认按**人工验收**精度书写（可执行的步骤清单 + 期望结果）。
- 若未来引入自动化回放（录制/比对设施），用例升级为脚本化锚点，但语义判定标准不变。
- 转生验收 = 全部 `[MUST]` 锚点通过 + `[SHOULD]` 偏离留痕 + `[CURRENT]` 自由。
